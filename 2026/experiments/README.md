## 设计原则

1. **跑真实流量，不用仿真器。** 分布式作业是真实进程，跑在各个 network namespace 里，通过真实的内核协议栈通信；网络条件用 `tc` 施加。
2. **一个实验床贯穿始终。** 从两个 namespace 起步，长成多跳网络，再长成 leaf-spine 迷你数据中心，后面的计算作业都在它上面跑。每个实验的产出（拓扑脚本、测量工具、作业代码）会被后面的实验复用。
3. **一个指标贯穿始终。** 后半程所有实验都回答同一个问题：作业完成时间（Job Completion Time, JCT）是多少，其中多少花在网络上，怎么把它降下来。
4. **每个实验走“预测、测量、解释”三步。** 先用模型估算，再实测，最后解释差距。实验报告的重点是解释，不是截图流水账。
5. **任务分三层。** 基础任务人人完成，进阶任务拉开区分度，挑战任务为综合项目铺路。

## 各实验内容

### Lab 1　从一根虚拟网线到多跳网络

指导书：[`01/README.md`](01/README.md)　｜　脚本：`01/ns_topo.sh`（实验床，后续实验复用）、`01/break_topo.sh`（故障盲测）

拓扑的搭建与抓包验证已经在讲义的动手模块里跟做过（[`network.md`](../docs/network.md) 模块六、[`switching_routing.md`](../docs/switching_routing.md) 模块五与六），本实验**不重复这套搭建过程**，而是在它之上往前一步：课上负责看懂现象，课后负责做出产出。

- **做什么**：
  1. **基础**：手工补全第 02 讲模块 6.4 留下的右侧机架；再跑通并**读懂** `ns_topo.sh`，说清它靠什么做到重复执行不报错、这个做法的代价是什么。
  2. **进阶**：改脚本把拓扑扩展到第三个机架（`10.0.3.0/24`，`r2`–`r3` 走 `10.0.23.0/30`），数清每加一个机架要新增多少条静态路由、改动几台设备——条数按 $N(N-1)$ 增长，这就是 Lab 2 的动机；再用 `tc netem` 给路由器互联链路加延迟，先预测再实测 `ping` 的 RTT 变化。
  3. **挑战**：故障盲测——用给定脚本随机破坏拓扑中的一处（接口未 up、`ip_forward=0`、缺回程路由、地址写错网段等），按第 02 讲 4.2 节的定位清单找出它并说明判据；有余力再把路由器互联链路改成 `/31`（RFC 3021）。
- **产出**：带 `up` / `down` 的拓扑脚本，所有后续实验复用；以及一份“每加一个机架，静态路由怎么涨”的观察记录——它是 Lab 2 的直接动机。

### Lab 2　让网络自己找路

指导书：[`02/README.md`](02/README.md)　｜　代码：`02/lsrd/`（守护进程骨架，给定约 550 行，学生写约 250 行）、`02/tests/`（离线单元测试）、`02/topo.sh`（三角形 / 三机架环实验床，复用 Lab 1 的脚本并删掉静态路由）、`02/run.sh`（启停与查看）、`02/probe.py`（单向探针）、`02/break_lsr.sh`（控制平面故障盲测）、`02/forge_lsa.py`（伪造 LSA）

第 03 讲在三角形实验床上看过 FRR 的 OSPF 怎样建邻、泛洪、算路、写内核，并留下三个数字：拔线 0 丢包、静默故障 34.6 秒、cost 改动后 ECMP 分流。本实验在**同一张实验床**上，按一页纸的协议规范（LSR-lite v1：JSON over UDP，规则 R1–R9）用 Python 写一个简化的链路状态路由守护进程 `lsrd`，把这三个数字自己做出来。第 04 讲课上一起写 Hello，其余课后完成。

- **做什么**：
  1. **基础**：实现 Hello 邻居发现（R1–R2）、LSA 泛洪（R3–R6）、Dijkstra（R7），结果用 `ip route` 写进内核（`proto 200`，R8）；只靠 Dead 定时器时拔线，用探针测数据流中断（约 8 秒），解释与 FRR 0 丢包的差距。
  2. **进阶**：订阅 `ip monitor` 让守护进程听见内核的链路事件，中断降到约 0.1 秒，把收敛拆成检测 / 泛洪 / 合并等待 / 计算安装四段；三台都在跑时挂上第三个机架，只重启 r3、不改任何旧设备——填完 Lab 1 那张表的最后一列；改 cost，装 ECMP，与内核的哈希分流对账。
  3. **挑战**：Ack 与重传做可靠泛洪（R9），用确定性的丢包窗口验证；控制平面故障盲测（六种：单向阻断、双向静默、定时器不一致、router id 冲突、只算不装、静态路由残留）；伪造 LSA，看 R6 挡得住什么；与同学的实现互操作（选做）。
- **产出**：路由守护进程，Lab 3 起的实验床不再手配静态路由。学生第一次量化“网络事件如何打断上层业务”。
- **参考**：[`2025/experiments/03`](../../2025/experiments/03/) 的类 OSPF 框架（去年邻居静态配置、不写内核路由表；今年骨架重写）。

### Lab 3　搭一个迷你数据中心

指导书：[`03/README.md`](03/README.md)　｜　代码：`03/topo.sh`（学生骨架，Lab 4–9 复用）、`03/measure.py`（定量传输与按流抓包汇总）、`03/overlay_down.sh`（登记资源的幂等清理）、`03/transfer.py`（应用字节回执）。第 05 讲六组课堂观察仍由 `03/classroom.sh` 支撑。

- **基础**：补全机架接入、上联与自检（含 12 条路由的 ECMP 核对），接入自己的 `lsrd --ecmp`（未完成 Lab 2 ECMP 时可用参考实现，自己的实现记附加分）；在收发两侧均分散的固定路径上比较 100/50 Mbit/s，按单向容量计算 1:1/2:1 收敛比，用 `tc` 计数把首部开销折算为帧级下界；复现交换与路由边界。
- **进阶**：固定六轮自然 ECMP，按 SYN 与数据出口分类同路／分路，解释未出现的分组和证据边界；自建双租户 VXLAN，在固定共享上联下比较 A 独占与 A+B 并发。
- **挑战**：按 VNI 与内层五元组识别目标连接，用 `ip route get` 复算 VTEP 选路，对照每条前失效／只失效一次／钉路三组，说明外层源端口与 VTEP 路由缓存的关系；用实际 TCP 选项、MTU、帧长和五轮中位数检验封装效率模型。
- **产出**：接口稳定的数据中心实验床、可复核的测量记录。任务 6–8 为连续选做链，可整体跳过；任务 5 不依赖 overlay。
- **验证**：2026-10-05 在 Ubuntu 24.04 / Linux 6.8 的备课沙箱中，临时拓扑补全副本与 Lab 2 参考路由通过修订后容量、六轮 ECMP、租户隔离和共享、源端口三组对照、五轮封装效率测量；2026-10-07 在 Ubuntu 26.04 / Linux 7.0 的 x86_64 虚拟机中复测扩展自检、任务 3 两档与 `tc` 计数、附加诊断和重新设计的任务 7。详见指导书的验证范围与 [`03/MAINTENANCE.md`](03/MAINTENANCE.md)。仓库学生 TODO 保持留白，学生实现和其他环境须独立验收。

### Lab 4　给网络做体检

- **做什么**：用 `iperf3`、`ping`、`ss`、`tc netem` / `htb` 建立测量方法（预热、重复、置信区间，识别单机 CPU 争用带来的干扰）；写一个工具，自动输出任意拓扑中节点两两之间的带宽和延迟矩阵。
- **产出**：“网络画像”工具，Lab 9 的调度器直接以它为输入。

### Lab 5　incast：复现与缓解

- **做什么**：让 N 个发送端同时向 1 个接收端回传数据，在浅缓冲下复现吞吐塌陷；对比 CUBIC、BBR、DCTCP（配合 ECN 标记）；再用发送端 pacing 缓解。
- **产出**：理解分布式计算里“多打一”通信模式的代价。
- **参考**：[`2025/experiments/04`](../../2025/experiments/04/) 的 `SO_TXTIME` 代码。

### Lab 6　长尾延迟与对冲请求

- **做什么**：写一个 fan-out 服务，1 个前端并发请求 N 个后端；给 1% 的请求注入慢响应，测量 P50 / P99 随 fan-out 增大而放大的规律；实现对冲请求（hedged request），量化它的收益和额外负载。
- **产出**：理解“最慢的一个决定整体”，为后面的 barrier 和 straggler 做铺垫。

### Lab 7　分布式作业的时间花在哪

- **做什么**：实现一个迷你数据并行作业（参数服务器结构，只用 numpy 和 socket），在实验床上运行，把 JCT 拆成计算、通信、等待三部分；改变带宽和延迟，拟合 α-β 代价模型；把 worker 分到不同机架，观察跨机架瓶颈和 straggler 效应。
- **产出**：贯穿后续实验的工作负载和 JCT 基线，Lab 8、Lab 9、综合项目复用。

### Lab 8　实现 Ring AllReduce

- **做什么**：用 Ring AllReduce 替换 Lab 7 的参数服务器，实测结果与理论通信量 $2(N-1)/N$ 对照；在 leaf-spine 上比较随机环序和拓扑感知环序。
- **产出**：第一个“只改通信方式、计算不变、作业变快”的实证。

### Lab 9　算网协同调度

- **做什么**：
  1. 用 Lab 4 的网络画像决定 worker 放置，真实运行，对比随机、同机架优先、代价模型评分三种策略的 JCT。
  2. 用 cgroup 限制 CPU，造出算力不同的节点，分布在不同网络距离上；实现请求分发器，对比“就近”“最空闲”“算力 + 网络联合代价”三种策略。
- **产出**：算网融合的完整闭环：感知网络、感知算力、联合决策。

### 综合项目　算网融合挑战赛

统一给定拓扑、异构算力和一组作业，各组自由组合放置、环序、路由、流控、对冲等手段，目标是总 JCT 最低。用统一脚本评测并做排行榜；展示时必须解释每个手段各贡献了多少。

## 已知风险

- **单机 CPU 争用会污染测量。** 所有 namespace 共享同一台虚拟机的 CPU。链路带宽要用 `tc` 压到 100 Mbit 至 1 Gbit 这一档，让瓶颈落在网络上而不是 CPU 上。
- **Lab 5 的具体机制需要实机验证。** DCTCP 依赖 ECN 标记；pacing 倾向用 `fq`，而不是去年的 `SO_TXTIME` + ETF。它们在 veth 上的实际表现尚未验证。
- **Lab 9 需要 cgroup v2。**
- **时间没有余量。** 各实验周数相加为 12 周，加上综合项目，15 周排满。需要缓冲时，跳过 Lab 3 的进阶任务（VXLAN 多租户）。

## 技术栈

Bash 写拓扑；Python 3 加 `uv` 写作业和工具，依赖只有 numpy 和 pyyaml；其余用系统自带的 `iproute2`、`tc`、`iperf3`、`tcpdump`。C 不作要求。
