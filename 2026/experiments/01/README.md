#### 任务 4　给链路加延迟：先预测，再实测

`tc netem` 可以在任意接口上人为制造延迟、抖动和丢包。本任务只用延迟。

```bash
# 10. 先量基线：跨机架的 RTT
sudo ip netns exec h1a ping -c 10 -q 10.0.2.11
```

本机实测的基线约为 `0.07 ms`（namespace 之间是内存拷贝，几乎没有传播时延）。

**先写下你的预测，再往下做**：

- 在 `r1` 的上行口 `r1-r2` 上单向加 20 ms 延迟，`h1a → h2a` 的 RTT 会变成多少？
- 如果在 `r2` 的 `r2-r1` 上也加 20 ms，RTT 又是多少？
- 同机架的 `h1a → h1b` 会受影响吗？

```bash
# 11. 在 r1 的上行口加 20ms 单向延迟
sudo ip netns exec r1 tc qdisc add dev r1-r2 root netem delay 20ms
sudo ip netns exec h1a ping -c 10 -q 10.0.2.11

# 12. 在对端也加 20ms
sudo ip netns exec r2 tc qdisc add dev r2-r1 root netem delay 20ms
sudo ip netns exec h1a ping -c 10 -q 10.0.2.11

# 13. 对照：同机架通信不经过这条链路
sudo ip netns exec h1a ping -c 5 -q 10.0.1.12

# 14. 查看与清除
sudo ip netns exec r1 tc qdisc show dev r1-r2
sudo ip netns exec r1 tc qdisc del dev r1-r2 root
sudo ip netns exec r2 tc qdisc del dev r2-r1 root
```

报告里给出**预测值、实测值、以及差距的解释**。重点解释这两件事：

1. `netem` 挂在 `root` 上，作用的是**出方向（egress）**。这对"单向加延迟，RTT 增加多少"意味着什么？
2. 实测值与预测值的偏差有多大？偏差来自哪里（`ping` 的时间戳精度、调度延迟、单机 CPU 争用）？

> [!NOTE]
> 本任务的具体数值**未在课程仓库的验证环境中实机跑过**（该环境的内核缺少 `sch_netem`）。命令本身是 `tc` 的标准用法，但如果你的实测结果与预期有系统性偏差，请在报告中如实记录，并告知助教。

## 五、故障排查

| 现象 | 可能原因 | 怎么查 |
| :--- | :--- | :--- |
| `Operation not permitted` | 没加 `sudo` | network namespace 操作需要 root |
| `Cannot open network namespace "xxx": No such file or directory` | 实验床没搭 / 已被拆掉 | 重新执行 `ns_topo.sh` |
| 脚本报 `RTNETLINK answers: File exists` | 上次实验残留 | 脚本会自动预清理；若仍报错，先 `ns_topo.sh down`，再 `ip link show type veth` 手工检查残留 |
| 同机架能通、跨机架不通 | 路由器没开转发，或缺路由 | `sudo ip netns exec r1 sysctl net.ipv4.ip_forward`；`sudo ip -n r1 route show` |
| 只有某一台主机不通 | 它的接口没 up、地址写错、或缺默认路由 | `sudo ip -n h1b addr show`、`sudo ip -n h1b route show` |
| 网关 ping 不通，但同机架的邻居能通 | 网关地址配在了桥端口而不是 bridge 设备上 | `sudo ip -n r1 addr show br1` |
| `tc: Specified qdisc kind is unknown` | 内核缺 `sch_netem` | 见第二节的工具检查 |
| `traceroute: command not found` | Ubuntu 默认不带 | `sudo apt install traceroute`，或改用 `tracepath` / `ping -t` |

## 六、思考题

1. **网桥为什么不需要配 IP**
   实验床里 `br1` 配了 `10.0.1.1/24`，但那是因为它兼任网关。如果 `r1` 只做交换、不做网关（网关在别处），`br1` 还需要 IP 吗？Docker 的 `docker0` 为什么有 IP？

2. **路由能不能少配几条**
   三机架拓扑里，`r1` 需要两条路由分别指向 `10.0.2.0/24` 和 `10.0.3.0/24`，而它们的下一跳是同一个。有没有办法用**一条**路由覆盖两个网段？这样做的前提是什么？如果机架 3 的网段是 `10.0.7.0/24` 还能合并吗？
   *提示：第 02 讲 3.3 节，以及 CIDR 的地址聚合。*

3. **脚本的幂等与真实运维**
   本实验的脚本靠"先拆后建"实现幂等。真实的数据中心不可能为了改一条路由就把整个网络拆掉重建。那么真实的网络配置工具（Ansible、NETCONF、各家的 SDN 控制器）是怎么做到幂等的？它们付出了什么代价？

4. **故障的可观测性**
   任务 5 里有两对故障从源主机看现象完全一样。如果你是这个网络的运维，要在**故障发生时自动区分**它们，你会在哪些设备上采集什么指标？
   *提示：想想哪些计数器会变——`ip -s link`、`nstat`、`ip -s neigh`。*

5. **延迟加在哪里**
   任务 4 把 `netem` 加在了路由器的接口上。如果改成加在主机 `h1a` 的接口上，`h1a → h2a` 和 `h1a → h1b` 分别会受什么影响？哪一种更像真实世界里"这条链路很慢"？
