                        涉及原讲义：3.1–3.5 节。

                        2. ●● 原讲义 3.2 节列出四种 fib_multipath_hash_policy。（1）同一对主机 h1a → h3a 开 8 条 TCP 连接，策略 0 与策略 1 下分别预期怎样分布？（2）为什么讲义要求先读取当前值再解释现象，而不能只说“ECMP 默认按五元组”？在一个新建的 network namespace 里读到的值通常是多少？（3）讲义说本实验床里“相同五元组的新 TCP 连接可能选到不同上联”，这与“同一组哈希输入选择同一个下一跳”矛盾吗？

                        3. ●● 两条上联各 50 Mbit/s、主机接入 100 Mbit/s。（1）一条 TCP 连接在常规按流 ECMP 下最多约多少？为什么不能把两条上联加起来？（2）8 条连接最多约多少，受哪两项约束？原讲义 3.5 节测得的 47.59 与 93.52 Mbit/s 各对应哪个约束？（3）若要一条连接同时利用两条路径，需要哪一类机制，主要代价是什么？

                        十一、从程序员视角再想一步

                        1. 需求、资源与映射分开建模

                        流量矩阵、拓扑与容量、路由与哈希分别回答“要传什么”“有什么”“怎样落到资源上”。你写过的调度器、负载均衡器或数据库分片里，哪一部分对应“映射”？只调“资源”不看“映射”时，会出现什么样的误判？

                        2. 哈希分散的是“个数”，不是“负载”

                        ECMP 按流哈希，和缓存、数据库按键哈希分片是同一类做法。热点键、大对象与大象流有什么共同点？除了换一个哈希函数，还能怎样处理“一个键就占满一个分片”的情况？

                        3. 先算下界，再看测量

                        maxe8De/Ce 只用一张表就能算出。测量值远高于下界时该查什么，远低于下界时又该怀疑什么？在你写的程序里，有没有类似“先估一个数量级再测”的习惯？

                        4. 名字空间隔离不等于资源隔离

                        VNI 让两个租户用同一套地址而互不可见，却仍然共享上联。容器、虚拟机与多租户数据库里的“吵闹邻居”问题和题 31 丙有什么相同？要给某个租户“保证”资源，需要在哪里分类、预留和调度？

                        5. 部分失败比全部失败更难发现

                        题 28 中只有走 r6 的探针中断，题 31 乙中只有一半主机对不通。单一健康检查（一个 ping、一个端口）为什么容易漏掉这类故障？你会怎样设计探测，让它覆盖不同的路径或分片？

                        6. 期望状态要和实际状态对账

                        题 31 乙里，路由进程记得自己“装过”的路由，内核里却已经没有了。第四讲回顾第十一节也讨论过 installed 这本账。怎样的对账循环既能及时发现差异，又不会因为频繁读写系统状态而带来新的问题？
